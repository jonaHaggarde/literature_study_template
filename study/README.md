# study/

A single-topic literature study: drop PDFs in, let an AI assistant build
a searchable, citation-grounded catalog of them, and track its own
coverage gaps against a scope you define. See the repo root `README.md`
for the template-level pitch; this file covers setup and day-to-day
mechanics.

## Folder structure

```
study/
  README.md              <- this file
  workflow-diagram.md      <- graphical overview of the whole process (Mermaid)
  catalog.md              <- master index. Read this FIRST, always.
  reference-index.md       <- every processed document's own references, deduplicated — grep for new leads
  manifest.json             <- tracks which PDFs have been converted (hash-based)
  decisions.md               <- decision/conclusion log, grounded in the literature (optional to use)
  scripts/
    setup.ps1 / setup.sh        <- one-time environment setup
    convert.py                   <- converts PDFs/ -> notes/, updates catalog.md, skips unchanged files
    build_reference_index.py      <- rebuilds reference-index.md from notes/ — rerun after adding documents
    build_gaps_index.py            <- rebuilds topics/gaps.md's auto-aggregated section from dossiers
    validate_repo.py                <- structural health check + --fix, rerun after every batch
    requirements.txt
  templates/
    note_template.md          <- reference only, shows the format convert.py generates
  ai_instructions/            <- read this first in every AI session — see ai_instructions/README.md
    README.md
    scope.md                   <- what this study is about — fill in before real work starts
    catalog-schema.md            <- catalog.md field definitions and allowed values
    workflow.md                   <- the operational playbook
  project_documents/           <- your own primary materials (project brief, purpose, etc.)
  PDFs/                          <- your source PDFs (NOT committed to git, see below)
  notes/                          <- one .md per PDF, generated by convert.py
  topics/                          <- synthesis dossiers for topics with many overlapping documents
  ideation/                         <- unverified brainstorming, structurally separate from decisions.md
```

## One-time setup

```powershell
cd study
.\scripts\setup.ps1        # or ./scripts/setup.sh on macOS/Linux
```

Creates `.venv/` and installs dependencies. Activate it afterward with
`.venv\Scripts\Activate.ps1` (`source .venv/bin/activate` on macOS/Linux).

## Getting started

1. Drop your own project materials into `project_documents/` (a project
   brief, proposal, anything explaining why this study exists).
2. Open an AI coding assistant here and ask it to read
   `ai_instructions/README.md`. Its first job is helping you fill in
   `ai_instructions/scope.md` — everything downstream (gap-flagging in
   particular) depends on that being real.
3. Drop PDFs into `PDFs/` and work through "Adding PDFs" below.

## Adding PDFs

1. Drop new PDFs anywhere under `PDFs/` (subfolders are fine, the script
   recurses).
2. Run:
   ```powershell
   python scripts\convert.py
   ```
   It hashes every PDF, skips anything already converted and unchanged,
   and for everything new/changed writes a `.md` file into `notes/`
   (mirroring the `PDFs/` path) and appends a stub entry to `catalog.md`.
3. Ask your AI assistant to fill in the TODO fields (abstract, tags,
   type, contribution, key findings, implementation notes) for the new
   entries — see `ai_instructions/workflow.md` for exactly what's
   expected. This should be a full, non-lazy read of each document, not
   just enough to write an abstract. (Title/authors/year are pre-filled
   from the PDF's own metadata where available — often wrong or stale,
   so verify rather than trust it.)
4. Rerun the reference-index builder so each new document's own citations
   become searchable leads for finding the *next* one:
   ```powershell
   python scripts\build_reference_index.py
   ```
5. Run the repo health check after every batch (not per-PDF):
   ```powershell
   python scripts\validate_repo.py --fix
   ```
   `--fix` mechanically corrects tag casing and regenerates the
   Comparison & survey papers quick-reference list — neither ever needs
   hand-editing. The checks themselves cover catalog/notes/manifest sync,
   stray TODOs, schema conformance, likely-duplicate entries by fuzzy
   title match, dossiers having their Open-questions section, and
   reference-index.md freshness. Fails (exit code 1) only on real
   problems. This catches sync bugs, not factual accuracy — for that,
   spend two minutes running 2-3 real discovery queries against the
   freshly-updated catalog and sanity-check the results by eye.
6. If any `topics/*.md` dossiers were added or updated, run
   ```powershell
   python scripts\build_gaps_index.py
   ```
   to regenerate the auto-aggregated part of `topics/gaps.md` from their
   Open-questions sections.
7. If a PDF is a scan and comes out with a `LOW TEXT YIELD` warning, OCR
   it first and re-run:
   ```powershell
   ocrmypdf PDFs\scan.pdf PDFs\scan.pdf --skip-text
   python scripts\convert.py
   ```
   (`pip install ocrmypdf`, plus Tesseract + Ghostscript — see
   https://ocrmypdf.readthedocs.io/en/latest/installation.html)

## How the AI should use this repo

See `ai_instructions/README.md` — that folder is the actual operating
manual (scope-checking, the catalog schema, the query playbook, and how
gap-flagging works). This README only covers human-facing setup. For a
graphical overview of the whole process, see `workflow-diagram.md`.

## Copyright note

**Keep this repo private if your sources are copyrighted.** `PDFs/` is
gitignored (large binaries, and you likely don't want to distribute
copyrighted material), but `notes/` contains substantial extracted text
from those same sources. That's fine for a private study; it is not fine
to make public. Double-check the repo's visibility before pushing if
`notes/` might contain copyrighted extracted text.
