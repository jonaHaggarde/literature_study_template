# Catalog

Master index of every document in this study — the full per-entry
record.

**Don't read this file in full.** Read `catalog-index.md` instead: it is
one line per document, generated from this file, and it carries what you
need to decide *which* entry to open. Come here for a specific entry and
grep out the single `<!-- entry:ID -->` block you want. That split is
what keeps the per-session read cheap as the corpus grows into the
hundreds of documents; reading this file whole does not scale, and
pretending otherwise is how a study's context budget quietly disappears.

Each entry is a fixed block of fields (grep-friendly, one `key: value`
per line) between an `<!-- entry:ID -->` / `<!-- /entry -->` comment
pair. `scripts/convert.py` appends a stub block for every newly-converted
PDF; fill in the rest afterward — see `ai_instructions/workflow.md`.

Field definitions and allowed values: `ai_instructions/catalog-schema.md`.
Tag vocabulary: `topics/vocabulary.md`.

After editing entries here, rebuild the index:

```
python scripts/build_catalog_index.py
```

Example entry format (not a real document — copy this block below the
line, replace the ID and fields; `scripts/validate_repo.py` skips an
entry literally named `EXAMPLE` so this reference block doesn't trip
validation, but don't leave a *real* entry using that ID):

```
<!-- entry:EXAMPLE -->
title: Example Title
authors: A. Author, B. Author
year: 2026
type: paper
approach: example method
contribution: experimental-validation
compares:
tags: example-tag
note: notes/example.md
source: PDFs/example.pdf
summary: The result with its numbers and the rig/dataset/population it was measured on. The comparison verdict, and the authors' own admitted limitation. Never a neutral restatement of the document's own abstract — see ai_instructions/catalog-schema.md.
<!-- /entry -->
```
