# Known gaps

A running list of comparisons or coverage that would be useful but don't
exist in this collection yet. The point isn't completeness for its own
sake: it's knowing when an answer rests on solid coverage in this
collection versus when it's really "nobody's covered this yet, more
sourcing is needed."

Every gap entry should be checked against `ai_instructions/scope.md`
before being logged — something genuinely out of scope is not a gap,
it's expected absence, and doesn't belong here.

This file has three sections with different upkeep rules:

## From dossiers (auto-aggregated)

Regenerated from every `topics/*.md` dossier's `## Open questions`
section by `scripts/build_gaps_index.py` — **do not hand-edit the block
below, it will be overwritten.** Run the script after adding or updating
a dossier:

```
python scripts/build_gaps_index.py
```

## From decision trees (auto-aggregated)

Every alternative that a decision tree under `../../ideation/` names but marks
`identified`: listed, never examined. A tree shows what was on the table; the
dashed boxes in it are what nobody has looked at, and those are gaps by
construction. Regenerated by the same script (**do not hand-edit the block
below**), which skips the templates and any tree that does not validate. The
list is mechanical and does not judge scope: an unexamined alternative may be
out of scope, which is expected absence and not a gap, so `/gap-check` checks
each against `ai_instructions/scope.md`.

## Flagged directly (not yet a dossier)

Things noticed mid-session — during PDF processing or a conversation —
that are in scope but thin or absent in the catalog, before a dedicated
`topics/*.md` dossier exists to formalize them. Freeform, never
auto-overwritten; move an item out once a real dossier covers it (its
"Open questions" section will then pick it up in the auto-aggregated part
above).
