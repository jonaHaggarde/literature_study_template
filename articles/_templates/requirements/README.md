# requirements

Version 1 of the requirements, written after the review. Two kinds, kept apart in the
article but both checked against in practice.

| | Primary (`P-`) | Derived (`D-`) |
|---|---|---|
| What | critical design parameters | follow from the primary ones |
| Value | defined, with unit and tolerance | from a derivation or argument, `TBD` until derived |
| Source | a document, person or rule | its parent requirements |

| | |
|---|---|
| Gate | `requirements` (medium). Skippable per project; the module is optional |
| Written from | the definition and the review |
| Grows | derived requirements are added after the concept decision, as new versions |
| Contains no | design choices; an assumption is never presented as a primary requirement |

See `requirements/README.md` at the repo root for why requirements wait for the survey.
