# Changelog

Versions of this template, so a fork can see what it is missing.

`TEMPLATE-VERSION` at the repo root records the version a fork started
from. Leave it alone in a fork except when deliberately pulling changes
in, and then update it to the version you pulled.

## How a fork pulls template changes in

There is no automatic path, and pretending otherwise would be worse than
saying so. Three options, cheapest first:

1. **Read this changelog and apply what matters by hand.** Always
   available, always correct, and the reason this file exists.
2. **Replace `study/` wholesale.** This is why `study/` is kept
   self-contained: it is the engine, and a fork that hasn't edited engine
   files can swap the whole directory and keep its own `PDFs/`, `notes/`,
   `catalog.md`, `topics/`, and `ai_instructions/scope.md`. Guard that
   self-containment — every project-specific file that leaks into
   `study/` makes this harder.
3. **Add this template as a git remote and merge periodically.**
   Realistic only for a fork that has not edited engine files at all.

## 2.0.0

Structural release. A fork on 1.x can adopt these piecemeal; the root
layout and the `abstract` → `summary` rename are the two that touch
existing content.

**Repo layout**

- Project content moved out of `study/` to the repo root:
  `decisions.md`, `ideation/`, `project_documents/`. `study/` is now
  purely the literature-review engine, which is what makes option 2
  above possible.
- New root stubs, each with a README stating what belongs in it *and
  what doesn't*: `theory/`, `meetings/` (one file per counterparty plus
  `internal.md`), `timeline.md`.
- Root `CLAUDE.md` now owns repo-wide conventions and routing;
  `study/CLAUDE.md` owns nothing but the read-order pointer, so the two
  cannot contradict each other.

**Conventions**

- **Citation convention for everything outside `study/`**: numbered
  `[1]`, `[2]` markers in order of first appearance plus a
  `## References` section, numbering local to each file, with plain
  links for sibling files. Stated in the root `CLAUDE.md` and repeated
  in each root folder's README.
- **Diagram convention**: a document describing a process, method, data
  flow, or ordering gets a mermaid diagram. Advisory — the validator
  fails on an unbalanced fence and only warns on a missing diagram.

**Delegation and agents**

- `.claude/agents/`: `corpus-scout`, `note-extractor`,
  `dossier-synthesist`. The worker scope contract moved out of
  `batch-orchestration.md` prose and into the `note-extractor`
  definition, which also makes the fresh-agent-never-fork rule
  structural rather than remembered.
- `.claude/commands/`: `/lit`, `/process-batch`, `/gap-check`.
- `.claude/settings.json`: a read-only permission allowlist.
- New `study/ai_instructions/delegation.md`: the tier table, the
  input/output-asymmetry rule, why each tier sits where it does, the
  document-derived vs. collection-derived split, and the measurement it
  all rests on.

**Catalog scaling**

- New `study/catalog-index.md` — one line per document, generated by
  `scripts/build_catalog_index.py`, read in full at the start of a
  session. `catalog.md` is now the per-entry lookup target, grepped one
  entry block at a time. The old claim that reading `catalog.md` in full
  stays cheap at 100+ documents was measured false at 85 and has been
  removed.
- **`abstract` renamed to `summary`**, with a hard rule: write the
  complement of the other fields — result with numbers, comparison
  verdict, the authors' admitted limitation, and why the document is
  here if that isn't obvious from the document itself. Never a neutral
  restatement of the document's own abstract. Warned, not failed, past
  ~400 characters.

**Validator**

- A non-canonical tag used by **two or more** entries now FAILs; a
  single-use one WARNs. A blanket failure contradicts `vocabulary.md`'s
  own policy that genuine one-offs may stay free-form.
- Warns past the three-to-five tag ceiling.
- Fails on placeholder field values (`n/a`, `none`, `-`) — the schema
  says to omit, and it no longer contradicts itself on this.
- Checks mermaid fence balance (fail) and missing diagrams in dossiers
  and `theory/` (warn).
- Checks `catalog-index.md` freshness, like `reference-index.md`.

**Other**

- `study/ai_instructions/mcp.md`: what a source-acquisition server
  unlocks, why no corpus server ships, and why domain-specific servers
  belong to the fork.
- `scope.md` gained a **working language** field — what language sources
  arrive in, what the study writes in, and what to do with a quoted
  passage.
- `convert.py` prints the copyright warning after every run.
- `project_documents/source-access.md` ships with a real default list of
  institutional, open-access, and discovery channels rather than an empty
  stub — the "nothing applied ships" rule is about the study's subject
  matter, not about the owner's own access, and a concrete starting list
  saves every fork retyping one.
